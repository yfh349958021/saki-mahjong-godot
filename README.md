# 天才麻将少女 · 技能麻将(Godot 纯代码版)

基于 **Godot Engine + 纯 GDScript** 的日麻对战游戏:内容是麻将对战,**抽牌概率由各角色的"技能"改写**——正是《天才麻雀少女》(Saki)式的"超能力麻将"。规则覆盖吃/碰/杠/加杠/抢杠/立直/一发/里宝/多响/流局听牌费/真实符数,八位可选角色。

## 背景:GitHub 调研结论

动手前检索了 GitHub,结论:

- **没有任何现成的、基于 Godot/GDScript 的"天才麻将少女"类技能麻将游戏**。
- 最接近的项目是 C++/Qt 技术栈的 [mjpancake](https://github.com/mjpancake/mjpancake)("A Saki mahjong simulator with high-quality occult implementation")及其 MIT 协议底层库 [libsaki](https://github.com/mjpancake/libsaki)(`girl/` 目录有 26 个角色的能力实现,含 CLI 无头入口)——但不是 Godot,无法直接复用。
- 纯逻辑算牌库方面,[MahjongRepository/mahjong](https://github.com/MahjongRepository/mahjong)(Python,向听/役/点数计算事实标准)、Tsumonya(C++)、[ssttkkl/mahjong-utils](https://github.com/ssttkkl/mahjong-utils) 等都是非 GDScript 实现,本作参考其算法思路(向听递归拆解、符数规则)后**全部用 GDScript 重写**。

## 架构:逻辑层与表现层彻底解耦

```
saki-mahjong-godot/
├── project.godot          # 主场景指向空壳 scenes/main.tscn
├── scenes/main.tscn       # 唯一场景:一个空 root Control(纯文本手写,无编辑器拖拽)
├── main.gd                # 表现层:纯代码动态构建 UI(真实日麻桌布局:四方座次、
│                          #   牌背、6 列牌河、立直牌横置、副露、中央宝牌指示、浮动行动按钮)
├── assets/tiles/          # CC0 日麻将牌贴图(FluffyStuff/riichi-mahjong-tiles,公共领域)
├── logic/                 # ─────── 逻辑层:全部 RefCounted,零 Node/UI 依赖 ───────
│   ├── tile.gd            #   34 种牌 / 136 张实体牌编码,红宝牌,±1 平移,牌谱简写解析
│   ├── wall.gd            #   牌山纯数组:洗牌(可复现 seed)/加权抽牌/墙顶挑选/数组重排
│   ├── shanten.gd         #   向听数:标准型(递归拆解+memo)/七对/国士,支持副露
│   ├── yaku.gd            #   胡牌判定/役种/简化符数/点数分配(枚举全部分解取最优)
│   ├── skill.gd           #   技能基类:被动加权钩子 + 主动效果接口
│   ├── skills.gd          #   八位角色技能的具体实现(见下)
│   ├── player_state.gd    #   手牌/牌河/副露/立直/振听/分数
│   ├── ai.gd              #   AI:最小向听择牌、受入数 tie-break、立直/鸣牌/技能决策
│   └── table.gd           #   对局状态机:原子步进 advance_one_step(),人类决策 API
├── tests/
│   ├── run_tests.gd       # 无头测试套件(152 项断言)
│   └── stats.gd           # 无头统计模拟(技能强度量化)
└── scenes/main.tscn
```

**逻辑层要点**(对应用户要求):

- 所有类继承 `RefCounted` 而非 `Node`,不引用任何 UI;`godot --headless -s` 下 100% 可运行(测试即证明)。
- 牌山就是一个纯数组(`wall.gd`),技能对它的操作只有三种纯数组手段:
  1. **概率加权抽牌** `draw_weighted()` —— 把均匀采样改成按 34 维权重向量的轮盘赌;
  2. **墙顶挑选** `peek_top()` + `take_id()` —— 看若干张并任取其一;
  3. **数组重排** `reorder_to_top()` / `take_kind()` —— 把想要的牌移到墙顶/取出改写。
- 表现层在 `main.gd` 的 `_ready()` 里用 `Control.new()`、`Button.new()`、`PanelContainer.new()`、`HBoxContainer.new()` 等动态构建,麻将牌是白底圆角 `StyleBoxFlat` + 文字(红宝牌自动标红),没有任何编辑器拖拽的场景。

## 八位角色的技能

| 角色 | 技能 | 机制(全部落在牌山数组操作上) |
|---|---|---|
| 宫永咲 | 「+1/-1」 | 主动 ×2/局:把手中一张数牌在同花色内 ±1 改写(优先从牌山取实体牌,取不到生成幻影牌) |
| 竹井久 | 「認識の改変」 | 主动 ×2/局:下一次摸牌改为**从墙顶 3 张里挑 1 张**(`peek_top` + `take_id`);AI 会在 1 向听且不立直时发动 |
| 天江衣 | 「負の自律作用」 | 被动:牌河里"别人不要"的牌,若正是自己需要的会**主动流向自己**(按需有用性 × 河中数量加权),无用的河牌则避开 |
| 原村和 | 「大魔神の精算」 | 被动:听牌时胡牌张概率 ×6,1 向听时进张概率 ×2.5 |
| 宫永照 | 「嶺上の絶対」 | 被动:岭上摸牌必然倒向进张(×6)与胡牌张(×12)—— 岭上开花之鬼,杠得越多越强 |
| 松实玄 | 「集まれドラ」 | 被动:宝牌会聚集到玄面前 —— 摸到宝牌的概率 ×4 |
| 新子憧 | 「牌の背中」 | 主动 ×1/局:感知牌山深处,把一张宝牌移到自己下一次摸牌的位置(`reorder_to_depth`) |
| 清水谷龙华 | 「恵みの雨」 | 主动 ×2/局:把刚摸的牌放回墙顶重新摸一张 —— 雨,也许会带来同一张牌 |

**完整规则实现**(此前版本的全部简化项均已补齐):

- **吃**:仅放铳者下家可吃,多种组合可选(AI 会择优并在不划算时放弃);吃后开门,三色同顺/一气通贯按食下减 1 翻。
- **一发 / 里宝**:立直后无鸣牌 intervening 的下一次和牌 +1 翻;里宝指示牌与宝牌同步定置,立直和牌时开示计数。
- **立直后暗杠**:采用"原听牌必须全部保留"判定 —— 暗杠视为已完成杠,枚举岭上换牌后原听牌是否仍成立,有害暗杠(实践中几乎全部)被拒绝。
- **流局听牌费**:荒牌流局时听牌者均分 3000 点(不听者按人头支付),结算界面标注各家听牌与否。
- **多响全符放铳**:双响/三家和各自满额由放铳者累计支付(不采用头跳),结算面板列出全部和牌者。
- **真实符数**:底符 20 + 雀头符(三元 2/风 2/连风 4)+ 面子符(明刻2/4、暗刻4/8、明杠8/16、暗杠16/32)+ 听牌形符(嵌张/边张/单骑 +2,双碰暗刻荣和按明刻)+ 门前荣和 10 / 自摸 2;平和荣和 30、平和自摸 20、七对子固定 25。
- 其余:碰/明杠/暗杠/加杠/抢杠(岭上开花 + 补宝牌指示)、立直(强制摸切)、振听(河含所听 kind 不可荣和)、宝牌/红宝牌、门前自摸、断幺九、平和(含听牌形校验)、役牌、一杯口/二杯口、三色同顺、一气通贯、对对和、三暗刻(暗杠计入)、混一色/清一色/混老头、七对子、国士/四暗刻/大三元/字一色/清老头(役满)、满贯~役满封顶点数。

唯一保留的简化:不支持途家(碰后加杠已支持)、九种九牌中途流局、连风雀头 4 符采用通用规则。

**联机对战**:主菜单「创建房间」生成**房间邀请码**(SMJ-开头的 Base32 编码 = 房主 IPv4:端口,Godot ENet 高层多人、主机权威模型)。朋友在主菜单输入邀请码即可加入同一房间;房间内每人**选择角色(不可重复)**,房主可**添加电脑并调整 AI 难度(简单/普通/困难)**,人数不足时开局自动补 AI;房主可在房间内调整规则:初始点数(25000/35000)、红宝牌数量(0/3)、食断、一发、里宝开关。对局中主机运行唯一真相 MTable,每步向各家下发"视角快照"(自家手牌真实、对手只有牌数),客户端动作经 RPC 上送由主机校验执行。跨网联机需房主做端口转发(默认端口 37564)后把邀请码换成公网 IP:端口;同一局域网开箱即用。

**界面与音频**:牌面/牌背采用 [FluffyStuff/riichi-mahjong-tiles](https://github.com/FluffyStuff/riichi-mahjong-tiles)(CC0 公共领域)矢量素材,4K 缩放清晰;自家手牌自动排序、居中显示,刚摸的牌固定在最右并与手牌留一张牌宽的间隔,打出后重新排序;悬停手牌会高亮自家牌河中的同种牌(现物/振听提示);右上角「⚙ 设置」可调整分辨率(最高 3840×2400)、背景音乐与吃碰杠音效音量、自定义牌桌背景图片,设置持久化到 `user://settings.cfg`;背景音乐与音效为程序实时合成(8 秒和风弦音垫循环、打牌撞击声、立直提示音),无需额外音频素材。

## 运行

需要 Godot 4.3+(本作在 4.7.2 下开发验证)。

```bash
# 玩游戏(窗口)
godot --path .

# 无头测试(首次需先 --import 生成全局类缓存)
godot --headless --import
godot --headless -s res://tests/run_tests.gd     # 152 项断言,退出码 0 即全过

# 无头统计模拟(每个技能 60 局)
godot --headless -s res://tests/stats.gd

# UI 冒烟:无头自动打完一整局后退出(退出码 0)
godot --headless -- --autotest

# 截图模式:窗口内自动演一局并保存 /tmp/saki_*.png
godot --path . -- --shots
```

## 无头验证结果(本机实测)

- `run_tests.gd`:**150 项断言全部通过 / 0 失败**,覆盖牌编码、洗牌可复现性、加权抽牌命中率、向听数(含副露/七对/国士)、役种与点数、四个技能的机制断言、30 局全逻辑模拟(含点数守恒校验)、同 seed 事件流逐字一致。
- `--autotest`:UI 层无头自动打完一整局并以退出码 0 结束。
- `--shots`:窗口模式自动演一局并截图(`/tmp/saki_*.png`),验证表现层渲染。
- **技能因果有效性**(`tests/paired.gd`,同 seed 同座位配对 A/B,完整规则下每技能 60 局):把技能座位换成素人再跑同一批牌——宫永咲 **41% vs 25%(+10pp)**、天江衣 **36% vs 25%(+7pp)**、竹井久 33% vs 25%(+5pp)显著正向;清水谷龙华 ±0、宫永照/松实玄 -1(需要杠/点数场合才发光,风味技能);原村和 -6、新子憧 -5→调参后 ±0(鸣牌加入后节奏加快,纯摸牌系技能被稀释,属规则环境下的平衡特性)。
- **整体统计**(`tests/stats.gd`,每技能 60 局):技能角色所在对局平均步数更短(咲 92 步 vs 基线 100 步)、流局更少;全部对局荣和 186 / 自摸 63,荣和路径充分活跃。
- 性能:向听计算带 memo 缓存,单次 AI 决策约 10~20ms,交互无感;300 局统计模拟约 16 分钟(纯逻辑,可无人值守)。
- 调参记录:衣的第一版(盲目吸河牌)曾把胜率拖到基线以下(-7pp),重写为"只吸引自己需要的河牌"后 +15pp;和的第一版只听牌时 ×5(≈0 效果),扩展为"听牌胡牌张 ×6 + 1 向听进张 ×2.5"后 +5pp;久的 AI 曾有"立直同回合预约挑选,挑到的胡牌张被摸切规则扔掉"的自毁 bug,已修复(将立直时禁止预约)。`tests/paired.gd` 支持单技能过滤(`-- nodoka`),可持续用于平衡调参。

## 设计说明

- **驱动模型**:`MTable.advance_one_step()` 是原子步(摸牌/打牌/响应结算)。表现层用计时器按节奏调用;无头模拟则循环调用到 `round_end`——同一套逻辑代码服务两种驱动。
- **人类决策点**通过 `phase` 状态暴露(`await_discard` / `await_peek` / `await_response`),UI 调 `human_*()` API 完成动作;AI 决策在 `MAI` 中同为纯函数。
- **可复现性**:牌山洗牌用 `RandomNumberGenerator` 播种,同 seed 全局事件流逐字一致(有测试保证),便于回归与复盘。
